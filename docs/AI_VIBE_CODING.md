# 用 Vibe Coding 扩展琛琳星球

这份项目适合用 AI 共同创作，但不适合把一句“做个小游戏”直接交给 AI 后让它重写整个入口文件。更可靠的节奏是：**先学习 → 再讨论 → 再写方案 → 再小步实现 → 每步验证。**

## 0. 先把项目规则交给 AI

本仓库根目录提供两份等价的项目协作入口：

- `AGENTS.md`：适合 Codex 等读取 Agent Instructions 的工具；
- `CLAUDE.md`：适合 Claude Code 的项目记忆；

它们要求 AI 先阅读、先交付方案，且禁止修改私密媒体、环境变量、历史部署目录。

如果你使用其他 IDE Agent，也可以把同样的规则放进其项目级 rules / instructions 文件。

## 1. 第一次对话：只读学习，不准改代码

先让 AI 阅读：

```text
README.md
docs/
src/data/loveData.js
src/main.jsx
src/styles.css
```

推荐直接发送：

```text
你是这个 Vite + React 小星球项目的协作设计师与工程师。
第一阶段只读：阅读 README.md、docs/、src/data/loveData.js、src/main.jsx、src/styles.css。
不要修改文件。请先用中文输出：
1. 当前功能与五个参考日地图；
2. 状态、背包、主题切换与 localStorage 的关系；
3. 我的 idea 最适合插入哪些组件；
4. 两到三个可选体验方案及取舍；
5. 最小可验收实现计划、涉及文件、风险和测试方法。
等我选定方案后，再开始小步实现。
```

**这一步的目标不是生成代码，而是判断 AI 是否真正理解了项目。** 如果它不能说明 Day2 → Day3 → Day5 的道具链、Day5 的主题切换或 Day8 的独立小游戏结构，就先要求它继续阅读。

## 2. 第二次对话：讨论 idea 与体验，不急着实现

给 AI 的输入应包含：

- 这一日想让用户感到什么；
- 完成时的情绪和奖励；
- 是否需要图片、角色、音效、动画或多人同步；
- 手机端是否必须支持；
- 哪些素材绝对不能公开。

要求 AI 输出至少两种方案。每个方案都应包括：

| 项目 | 必答内容 |
| --- | --- |
| 用户流程 | 从进入到完成的 3–7 个动作 |
| UI 结构 | 日历卡、独立 modal、全屏场景或导航页 |
| 状态模型 | localStorage / 云端字段、完成条件、重置方式 |
| 视觉 | 色板、角色状态、图片规格、动效节奏 |
| 风险 | 手机性能、无障碍、隐私、版权、失败回退 |
| 验收 | 可以手测的成功标准 |

先选一个方向，再让 AI 写 `docs/PLAN.md`。方案没有确定前，不要批准它改动大量 JSX/CSS。

## 3. 第三次对话：实施契约

在开始写代码前，让 AI 明确回答：

```text
- 会新增/修改哪些文件？为什么？
- 新 type、state、事件和背包道具的名字是什么？
- 如何避免破坏 Day1/2/3/5/8？
- 需要哪些图片、尺寸、格式与授权？
- 完成后运行哪些命令？浏览器要测哪些步骤？
- 如果效果不满意，如何只回滚本次功能？
```

大功能按“一个可玩闭环”拆分：先做入口与假数据，再做核心交互，再做奖励/动画，最后做移动端和视觉润色。不要把数据、组件、动画、云端和样式一次全部重写。

## 4. 实现后的必做验证

让 AI 每个小阶段都做：

```bash
npm run check
```

再要求它用浏览器实际检查：

- 首页 CTA 和顶部导航都能进入每日签到；
- 新日历格存在，任务完成前签到按钮禁用；
- 完成后可签到，刷新后状态正确；
- 键盘、触控和窄屏不失效；
- 无横向溢出、无控制台异常；
- `git diff` 只包含已同意的文件，没有 `.env.local`、私密媒体或 `dist/`。
