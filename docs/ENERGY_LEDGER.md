# 彩蛋积分与阶段目标

`src/energyLedger.js` 将累计积分与阶段目标分开：目标为 1314，达到目标后继续累计。100、459、669 的历史印章保留，新增 1314 印章。进度条最多填满 100%，积分数字不截断。

旧版本把积分截到 669，并只保留最近 80 次抽取。恢复时应先备份 `day_progress` 与能量活动日志，再将最后一笔未封顶的历史累计值与之后的独立抽取明细拼接；检查衔接处、后续未封顶日志以及重复抽取序号。同一剩余机会的并发写入不能简单重复计分。

恢复记录、原始快照及迁移脚本保留在被 Git 忽略的 `backups/`、`.cache/`，不提交账户历史数据。执行迁移使用 `updated_at` 条件更新；数据自审计后发生改变时终止，不能覆盖较新的抽取。

恢复后的 `energyLedger` 保存核实过的基准积分和时间。旧页面若重新写入 669，新代码仍能由基准与之后的抽取明细还原累计分数。新版本不再裁切明细，活动日志也保存本次 `gain` 和 `at`。

能量写入使用乐观并发检查：计算前读取版本，提交前核对版本，数据库更新还须匹配同一 `updated_at`。冲突或网络失败不会提前在本机显示成功，之后由自动同步读取云端确认状态。它能保护使用新版能量逻辑的页面；尚未刷新的旧页面不具备这项并发保护。

验证：`node --test scripts/*.test.mjs`、`npm run check`；浏览器检查彩蛋入口、随机抽取及次数扣减、旧印章和新目标、390px 布局及控制台。生产只核验恢复结果，不用真实剩余机会做测试。
